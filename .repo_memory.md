## Architecture and ownership

### Builtin Codex vs extension Codex

- Fact: Builtin Codex is server-only; `codex-ext` is the registered Codex extension at `extensions/codex_ext` with type `codex_ext`.
- Why it matters: platform logic and extension logic are intentionally separate, so changes for Codex extension behavior should target `codex-ext`, not the builtin server-only Codex path.
- Citations: `extensions/extensions.json:3-17`; `agent_log_server/server.py:8041-8049`

### Live Codex extension path

- Fact: The only live registered Codex extension path is `extensions/codex_ext`; `extensions/codex` was removed as dead code and tooling/package data now target `codex_ext`.
- Why it matters: this avoids editing the wrong extension tree and keeps schema/runtime work aimed at the path that the loader actually instantiates.
- Citations: `extensions/extensions.json:3-18`; `pyproject.toml:38-41`; `scripts/codex_schema_extract.py:5-6,86,155`

### Codex auth surface today

- Fact: Codex protocol/runtime include account auth schemas, but current `codex` and `codex-ext` clients only use model/thread/turn RPCs and do not call account methods yet.
- Why it matters: auth-related work still needs explicit client wiring; the schemas existing upstream does not mean the local extension already uses them.
- Citations: `extensions/codex_ext/protocol.py:172-179,281-288,313`; `extensions/codex_ext/runtime_protocol.py:594-675,819-842,1314-1320`; `extensions/codex_ext/client.py:303-305,328,437-543`

### Session picker binding

- Fact: Extension `session_picker` fields are rendered by `static/modals/settings_schema.js`, and `server.py` binds `settings.session` as a one-time thread/session selection.
- Why it matters: session binding behavior is shared and schema-driven, so new session-picker logic should plug into the existing modal/server path instead of inventing extension-specific selectors.
- Citations: `agent_log_server/static/modals/settings_schema.js:298-327,512-514`; `extensions/copilot_sdk/settings_schema.json:15-20`; `extensions/codex_ext/runtime_protocol.py:1194-1201`; `agent_log_server/server.py:5977-6005`

### Rollout picker ownership

- Fact: The rollout picker is a shared frontend resource for extensions; the generic frontend now exposes a provider hook for it, while Codex rollout transcript import lives inside each Codex extension package instead of `server.py`.
- Why it matters: rollout/session-import behavior must remain extension-owned, but the UI shell can stay generic. Future work should register picker providers from extensions rather than reintroducing server-owned `/api/appserver/rollouts*` routes or hardcoded generic Socket.IO rollout calls.

### Copilot CLI process CWD isolation

## Critical contracts

### Composer draft restore

- Fact: Failed sends restore drafts server-side via `meta["draft"]` + `draft_update` only when an extension returns `restore_draft: true`; visible failure uses the shared error contract.
- Why it matters: send-failure UX is backend-owned and opt-in, which avoids duplicate user-turn artifacts and keeps draft restoration consistent across extensions.
- Citations: `agent_log_server/server.py:6565-6706,7523-7624`; `extensions/__init__.py:1320-1335`; `TRANSCRIPT_CARD_CONTRACTS.md:269-290`

### Conversation error contract

- Fact: User-visible conversation errors use live `type: "error"` and replay `role: "error"`; `rpc_error` is reserved for app-server pending-RPC failures.
- Why it matters: extensions and frontend rendering need one visible error contract for live and replay parity; `rpc_error` is not the generic user-facing lane.
- Citations: `TRANSCRIPT_CARD_CONTRACTS.md:222-248`; `extensions/copilot_sdk/router.py:1459-1496`; `agent_log_server/static/js/codex_agent/events/router.js:196-199`

### Token/footer ownership

- Fact: Footer token/context is backend-owned: routers must emit `context_window` in `token_count` / `token_usage`; frontend must not do extension-specific recovery.
- Why it matters: footer correctness depends on the backend delivering complete token metadata, so frontend patches should not try to reconstruct missing extension fields.
- Citations: `TRANSCRIPT_CARD_CONTRACTS.md:71-116`; `extensions/copilot_sdk/router.py:179-222`

### Transcript replay roles

- Fact: Legacy Codex rich replay for tool usage depends on transcript roles `mcp_tool` and `web_search`, not flattened `command` rows.
- Why it matters: replay fidelity for Codex tools still depends on those transcript role shapes, so router/storage changes must preserve them.
- Citations: `agent_log_server/server.py:4692-4816`; `agent_log_server/static/codex_agent.js:3134-3251`

### Runtime transport

- Fact: Runtime UI/backend contracts must stay Socket.IO-only; do not add HTTP fallbacks without explicit user approval.

- Fact: The repo already uses `python-socketio` `AsyncServer`, `AsyncClient`, `AsyncNamespace`, and multiple namespaces like `/appserver` and `/sidebar_ipc`.

- Fact: Both the main server and `mcp_agent_pty_server.py` derive a stable repo-root-based framework-shell secret from `~/.cache/framework_shells/runtimes/<fingerprint>/secret`.
- Why it matters: This is the framework-shell trust mechanism already present in the repo. It is useful background for process isolation work, but it is separate from the dedicated app-server IPC secret used for KB-origin Socket.IO notifications.

### Ask-user interaction IDs

- Fact: `agent-pty-blocks.ask_user` uses the conversation's own `conversationId` (from `CONVERSATION_ID` env var injected at MCP stdio launch) as the canonical `requestId`. No derivation, no hashing, no side-band registration. Each MCP server process is 1:1 per conversation and ask_user is synchronous per thread, so `conversationId` is collision-free. The old `canonical_ask_user_request_id()` hash helper and `_ASK_USER_REQUEST_ID_RE` regex have been removed.
- Why it matters: ask-user cards render with `requestId = conversationId`, the MCP tool registers its pending future under the same key, and the `/ipc ask_user_response` event resolves it by matching that key. Future ask-user work must use this conversationId contract and must not reinvent ID generation, side-band registration, or hash derivation.
- Citations: `mcp_agent_pty_server.py:2357-2449`; `extensions/codex_ext/router.py:1916,2494,2803`; `extensions/codex_ext_exp/router.py:1916,2494,2803`; `extensions/codex_ext/transport.py:656`; `extensions/codex_ext_exp/transport.py:656`; `extensions/codex_ext/runtime_protocol.py`; `extensions/codex_ext_exp/runtime_protocol.py`; `extensions/copilot_sdk/te2_runtime.py`

### Ask-user live bind seam

- Fact: Live Codex/Codex-exp `agent-pty-blocks.ask_user` calls bind on the `item/started` notification carrying an `item.type == "mcpToolCall"` tool item, not on an emitted `item/tool/call` server-request in the tested runtime path.

### Ask-user pending/resolved ordering

- Fact: Pending `ask_user` cards now carry backend-owned unresolved ordering (`order_id = -1`) in their persisted `meta.json` render event, and the resolved handoff must merge the recorded transcript metadata (`nid`, `card_id`, `order_id`) back into the broadcast event instead of letting the frontend invent a synthetic resolved card id.
- Why it matters: `ask_user` cards are two phases of one backend-owned transcript contract: pending/live in `meta.json`, then resolved in `transcript.jsonl`. Future `ask_user` work must keep unresolved state out of the transcript order lane, let transcript append assign the real positive order on resolution, and avoid reintroducing frontend-only `ask_user_resolved_*` identity hacks.

### Copilot MCP ask_user routing

- Fact: In `copilot-sdk`, `agent-pty-blocks.ask_user` must be intercepted before generic tool rendering: the client event queue handles the MCP tool start/complete events, persists a pending approval descriptor with `request_id = conversationId` and `card_id = tool_call_id`, suppresses the generic MCP tool row, and finalizes through `ask_user_interactions` on tool completion.
- Why it matters: Codex already special-cases this MCP tool, but Copilot’s generic tool router does not. - Fact: `codex-ext` thread resume treats `thread/status/changed` `idle` as virtual ack and fails fast on `mcp_startup_update` with `status.state = failed`.

- Citations: `extensions/codex_ext/transport.py:857-923,1016-1030`; `extensions/codex_ext/client.py:371-397,1019-1023`
