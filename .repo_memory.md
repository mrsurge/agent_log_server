# Repo Memory

## Memory and reference contract

This file is concatenated into agent developer instructions on every ALS-RS
conversation. Keep it compact, current, and limited to high-frequency invariants
that materially affect ordinary work.

The detailed architecture and implementation guide is
`ALS_RS_TECHNICAL_REFERENCE.md`. It is registered in the repo KB and is
searchable/readable with `kb_search`, `kb_info`, and `kb_read`. Before making an
architectural decision, search that reference and the canonical contract docs
instead of relying on this summary alone.

Maintenance rules:

- manually patch `ALS_RS_TECHNICAL_REFERENCE.md` whenever a durable contract
  changes; do not regenerate or mechanically rewrite it from memory
- mirror only the high-frequency consequence into this file
- move detail out of this injected file only after it exists in the reference
- current tracked source outranks historical notes, caches, logs, worktrees, and
  old user-message citations
- active source hierarchy is Rust server/static, Rust DTO/protocol crates, Python
  bootstrap/adapter, then extension-owned packages; `als_deprecated/` is parity
  history unless explicitly referenced

## Active ownership

- The active ALS-RS server, persistence, networking, TE2 integration, and browser
  source live under `rust/crates/als-server/src/`.
- The active frontend entrypoint is
  `rust/crates/als-server/src/static/codex_agent.ts`; `build.mjs` produces
  `rust/crates/als-server/src/static/dist/codex_agent.js`.
- Python owns only bootstrap and the generic extension adapter under
  `agent_log_server_rs/`. Provider-specific behavior belongs inside
  `extensions/<extension>/`.
- The only active builtin provider entries are `codex-ext` and `copilot-sdk` in
  `extensions/extensions.json`. There is no builtin provider fallback and no
  active `codex-ext-exp`.
- Rust must remain provider-neutral. Provider session, protocol, auth, model,
  planning, tool, approval, and event translation logic stays extension-owned.
- Detailed map: KB reference sections `Source hierarchy`, `Target architecture`,
  `Extension adapter protocol and transport`, and
  `Extension packages and provider notes`.

## Runtime invariants

- ALS-RS owns isolated data/cache/config roots, normally
  `~/.local/share/als-rs` and `~/.cache/als-rs`, and defaults to port `12459`.
- Rust owns Axum HTTP/static serving and socketioxide namespaces. Python is not
  an ALS-RS HTTP or Socket.IO server.
- The shared ask-user credential at `~/.cache/app_server/ipc_secret` is an
  intentional exception to root isolation. Inherited `FRAMEWORK_SHELLS_*`
  control-plane state is also preserved when ALS-RS is launched by FWS/TE2.
- The Python bootstrap exports roots/interpreter state and starts Rust. Rust
  starts and owns the generic Python extension adapter.
- Cargo-owned launches use a locked, source-fingerprinted final-binary cache:
  release is default, `als-rs --debug` selects debug, successful publication
  prunes older final binaries, and reusable Cargo target state remains intact.
  An explicit server binary bypasses this lifecycle.
- ALS-RS must work standalone. TE2 is a development/IDE integration surface, not
  a product runtime dependency.
- Never resolve symlinks in repo/runtime path handling. Use `TMPDIR` or a
  platform-appropriate temp directory, never hardcoded `/tmp`.
- Detailed map: KB reference sections `Non-negotiable invariants`, `Runtime and
  environment particulars`, `Python package and bootstrap particulars`, and
  `Rust adapter runtime wiring`.

## Transport and RPC

- Socket.IO is the browser control plane. The default transcript data plane is a
  dedicated binary `/ws/transcript` WebSocket; it is an explicitly approved
  exception to the prior Socket.IO-only rule.
- RPC namespaces use event `rpc`, JSON-RPC-shaped ack envelopes, and notification
  event `rpc.notify`. Primary namespaces are `/rpc/conversations`,
  `/rpc/settings`, and `/rpc/ui`; private MCP interaction uses `/ipc`.
- Socket.IO defaults to MessagePack on every namespace while preserving the
  JSON-RPC-shaped DTOs. `AGENT_LOG_SOCKETIO_SERIALIZER=json` switches the whole
  launch-owned server/browser/adapter/MCP lane to JSON for debugging.
- `/ws/transcript` uses versioned tagged MessagePack, negotiated gzip, bounded
  queues, and a page-lifetime client ID shared with composer authorship. It owns
  transcript windows and selected-conversation live/projection events only.
  Reconnect preserves card bounds, clears known recipe versions, and schedules
  a full `current` snapshot outside the serialized frame decoder; sequence gaps
  use the same single-flight resync path.
- `ALS_RS_TRANSCRIPT_TRANSPORT=rpc` explicitly restores the Socket.IO projection
  and notification path for debugging. There is no automatic fallback or dual
  delivery. Lists, drafts/selections, mentions, metadata, settings, UI, and MCP
  IPC remain on Socket.IO in stream mode.
- Frontend params must be JSON-domain safe before MessagePack encoding:
  undefined object fields are omitted and undefined array values become null.
- Extension adapter transport is newline-delimited JSON-RPC over direct child or
  Ferrous-owned stdio pipes. Rust owns framing/request matching; Ferrous owns
  optional observed process/pipe lifecycle.
- Pipe consumers use framework-shell output subscriptions and pipe writes, never
  concurrent direct stdout reads.
- Detailed map: KB reference sections `Browser transport and RPC contracts`,
  `Extension adapter protocol and transport`, and `Rust adapter runtime wiring`.

## Conversation lifecycle

- Existing harness conversations are transcript-first: reload/select replays
  local `transcript.jsonl` and leaves provider state cold.
- First live use follows `action -> cold miss -> extension resume -> resume ack
  -> retry once`. Do not eagerly resume merely because a conversation is opened.
- Codex reattach uses `thread/resume` with `excludeTurns: true`. History-bearing
  provider import is a separate extension-owned hydration path for a newly bound
  local conversation.
- `provider_session_id` is canonical provider identity.
  `conversation_id` is local harness identity and must never be substituted for
  a provider session id.
- Conversation fork is generic: Rust allocates/copies local state through
  `conversation.fork`; the extension forks provider state. Codex uses
  `thread/fork` with `excludeTurns: true`.
- `conversation.compact` and `conversation.shell.exec` remain explicit
  not-implemented ALS-RS controls.
- Detailed map: KB reference sections `Conversation, transcript, and lifecycle
  contracts`, `Conversations RPC namespace`, and `Current capability and
  limitation matrix`; canonical lifecycle doc:
  `AGENT_EXTENSION_INTEGRATION.md`.

## Transcript and card contracts

- Extension routers preserve live/replay parity: every replayable live event has
  a transcript record carrying the same fields.
- User-visible errors use live `type: "error"` and replay `role: "error"`;
  `rpc_error` is only for pending RPC failures.
- Footer token/context values are backend-owned. Routers include
  `context_window`; the frontend does not reconstruct provider metadata.
- Apply-patch/file-change tool cards are summaries. Standalone generic `diff`
  cards own visible patch bodies; routers do not duplicate those bodies into
  the related tool event or transcript entry.
- Raw new-file content received in a provider field named `diff` must become a
  real `/dev/null` unified diff before emit/persistence. Never header-wrap
  arbitrary Markdown/text as a fake patch. Non-add payloads require a valid
  hunk or recognized binary/mode/rename/copy metadata before diff emission.
- Custom approval cards are manifest-declared `ui.requestCards[]` modules loaded
  through the generic request-card runtime.
- Canonical docs: `TRANSCRIPT_CARD_CONTRACTS.md`, `APPROVAL_CONTRACT.md`, and
  `EXTENSION_PLANNING_CONTRACT.md`.

## Transcript projection and virtualization

- Rust owns one process-local durable transcript-card cursor per logical page
  client/conversation. A raw JSONL record, a semantic transcript card, and a
  browser layout row are distinct units and must never share cursor arithmetic.
- Browser requests are `tail`, `older`, `newer`, or `current`. Rust serves
  a 75-card window with 20-card shifts from a cached line-offset/card index.
  State-only and hidden records do not advance card count; grouped lifecycle
  records may update one card.
- Projection responses use `projection.unit: "transcript_card"`. Initial/resync
  stream snapshots carry all recipes; later deltas carry authoritative ordered
  card IDs/indexes/versions, removals, and only new/version-changed recipes.
  RPC debug responses remain complete `frame.format: "card_recipes"` windows.
  Bounds, `at_start`/`at_tail`, and runtime state remain authoritative; raw line
  counts are diagnostics only.
- Every durable recipe has a monotonic version and carries authoritative card
  ID/index/version/operation/scope metadata. Active recipes carry
  ID/index/operation/scope; both may carry optional parent identity. Repeated
  family/source snapshots reduce to one latest durable card. Active/unscoped
  rows participate in layout but never durable cursor math. A missing renderer
  becomes one visible diagnostic root instead of aborting window replacement.
  A fixed 1 MiB per-card projection limit likewise substitutes one
  identity-preserving error recipe; aggregate overflow remains explicit.
- Durable `transcript.jsonl` stays append-only and final-event-only. A separate
  bounded `TurnProjectionStore` reduces active assistant, reasoning, command,
  tool, subagent, diff, view, search, plan, notice, and compaction events.
- Adapter transcript append and replay projection share one per-conversation
  lock. Durable rows retire all active family aliases with matching lineage;
  terminal status clears orphaned active items. Full active state is fetched
  only with replay; lightweight notifications carry generation/revision/count.
- While pinned, live events append normally and completed card roots prune
  toward 75 without mutating the server cursor. Detached history buffers
  ordinary live cards while status/token/mode and blocking approvals stay
  current. Unresolved approvals and active rows are not pruned.
- Detached shifts require both the virtualizer's visible durable card-index
  range and measured prefix-summed edge geometry. The six-card trigger,
  12-card re-arm boundary, two-viewport/640px edge and live-tail runways, and
  20-card shift provide the neutral buffer. Hidden collapsed descendants,
  active rows, and unscoped live-only rows do not enter durable cursor math.
- A projection shift stays loading/programmatic through render, anchor restore,
  and settled layout. The structural top spacer is zero-height. Expanded card
  IDs survive only one overlapping in-memory replacement, never reload/storage.
- The Pretext virtualizer handles only geometry: prepared Markdown,
  width-dependent heights, prefix positions, overscan, measured placeholders,
  and card-ID anchor preservation. Logical records include parked placeholders,
  so the mounted subset may be smaller without changing the 75-card window.
  Collapse/expand remains an anchored measurement transaction.
- Detailed map: KB reference section `Rust-owned transcript projection`;
  canonical card definitions: `TRANSCRIPT_CARD_CONTRACTS.md`.

## Conversation list and composer synchronization

- Rust broadcasts complete `conversation.list.updated` snapshots with monotonic
  revisions. Reconnect fetches canonical list state in a fresh local revision
  epoch; newer live snapshots win races.
- Unreadable conversation metadata becomes a non-actionable corrupt diagnostic.
  Healthy rows remain available; list failure is explicit, never silently empty.
- Rust owns canonical draft text, revision, selection, and a process-local
  composer authorship gate.
- A focused client claims authorship. Draft/selection writes require the owning
  socket/client, current author epoch, and newer client sequence.
- Selections serialize against canonical text. Clients suppress stale
  same-origin events and remote-apply selection echoes.
- Sidebar mentions target one author socket with an operation ID. Without a live
  author, Rust performs one canonical persisted insertion and broadcasts it.
- Detailed map: KB reference sections `Conversation list resynchronization` and
  `Multi-client composer ownership`.

## Approvals and `ask_user`

- Generic live approvals persist in `meta.pending_approvals`. Resolution routes
  through adapter `approval.respond`, appends a `role: "approval"` handoff,
  removes pending state, and emits the authoritative handoff.
- `pending_approvals_revision` is monotonic. Frontends reconcile restore/live
  state by backend revision, not arrival order.
- `agent-pty-blocks.ask_user` is Rust-owned through private `/ipc`.
  `requestor_id` is stable `CONVERSATION_ID`; random `request_id` identifies one
  invocation.
- One live request is reserved per requestor. Replacement invalidates the old
  card/waiter. Only the exact live owner/request can accept a response.
- Pending ask-user cards are backend-owned and do not depend on frontend
  availability. Unresolved ordering is separate from final transcript ordering.
- Codex injection forces `supports_parallel_tool_calls = false`,
  `readOnlyHint = false`, and at least a one-hour timeout. This is scheduling
  protection, not a semantic protocol barrier; developer instructions also tell
  agents not to parallelize `ask_user`.
- Codex and Copilot suppress only the generic MCP tool row for this tool; Rust
  creates/persists the approval card.
- Detailed map: KB reference section `Approval and MCP interaction contracts`;
  canonical doc: `APPROVAL_CONTRACT.md`.

## Settings and extension UI

- Rust reads registered extension `settings_schema.json` files directly from the
  entry-owned root. Missing files yield an empty `schema_source: "missing_file"`
  schema; extension Python is not a settings-schema fallback.
- Schema fragments are extension-root-relative and reject absolute paths,
  traversal, invalid prefixes, and symlink escape.
- Dynamic selects, write-back, dependencies, conditional visibility, submenus,
  interactions, auth launchers, transient fields, and large option pickers are
  provider-neutral schema contracts. Do not hardcode provider field IDs or data
  shapes in Rust/shared frontend.
- Schema write-back is non-destructive unless clearing is explicit.
- Footer quick controls and provider status/usage are schema-declared semantic
  roles backed by generic adapter methods.
- Reasoning-effort choices come from actual per-model metadata; shared UIs never
  invent `low/medium/high` fallback options.
- Session/rollout import stores the provider binding and invokes extension-owned
  resume/hydration. Rust persists only normalized IDs/transcript events.
- Conversation Settings and Project share one tabbed modal shell while retaining
  separate renderer/action ownership. Unsaved settings survive tab switches;
  Project is disabled during pending new-conversation setup.
- Detailed map: KB reference section `Settings, schema, and provider runtime
  contracts`; schema contract: `worktrees/notes/SCHEMA_SETTINGS_CONTRACT.md`.

## TE2 integration and stateful windows

- Rust owns one persistent typed `/sidebar_ipc` client. It uses `rpc` /
  `rpc.notify` for CWD, file open, mentions, stateful windows, drafts, and inline
  agent-edit state. Narrow legacy events are cutover fallback only.
- The outbound Sidebar client resolves the TE2 server from injected
  `TE_FRAMEWORK_URL`, falling back to `TE_PORT` and then standalone port `8089`;
  ALS-RS's own HTTP listener remains `12459`. Network and server disconnects
  reconnect event-wise, and every Socket.IO connection re-registers the exact
  `als-rs` app peer before TE2 can target it.
- TE2 semantic readiness is posted after router construction, TCP bind, and
  server task startup. Readiness is separate from stateful window checkpoints.
- Stateful behavior is gated by TE2 `te2_host_id`. Cold slot hydration is
  client-local `conversation.get` + replay and does not call global
  `conversation.select`.
- `app.windowState.publish` validates host/conversation identity and asks TE2 to
  persist opaque restore state. `sidebar.window.focused` is only a transient
  mention-target hint.
- File navigation and review are separate: `sidebar.file.open` navigates;
  `sidebar.agentEdits.*` hydrates/reconciles review; `sidebar.file.edit` is an
  optional tracking/navigation signal.
- TE2 must request `sidebar.agentEdits.documentState.get` whenever it opens a
  file, regardless of tracking settings. TE2 is not the review-state authority.
- Before editing existing files, agents preflight TE2 drafts through
  `sidebar_drafts_list` or targeted draft-state tools and ask before overwriting
  meaningful user draft content.
- Detailed map: KB reference section `TE2, frontend, and project UI contracts`.

## Project modal and inline edit review

- Rust owns project git summaries/actions, conversation tracked-agent-edit
  ledgers, URI-scoped inline review state, and reverse patching.
- One canonical live diff feeds Project modal tracking, inline document
  projection, TE2 review publication, and optional file-edit notification.
- Project notifications refresh the summary only while the shared modal's
  Project tab is active.
- Accept/reject in Project modal and inline editor route through the same Rust
  implementation before review state is cleared/republished.
- Reverse patching is programmatic, whitespace tolerant, line-ending preserving,
  and strict about missing/mismatched modified-side lines and multi-file hunks.
- Strict metadata mismatch requires explicit confirmation before forced
  content-search fallback.
- Reject-all is one backend RPC: Rust snapshots newest-to-oldest and applies
  reverts sequentially, publishing each authoritative removal before final ack.
- Detailed map: KB reference subsection `Project modal and inline agent edits`.

## Extension packages and lifecycle

- Every extension manifest has a non-empty version.
- Ordered roots are builtin first and `${ALS_RS_DATA_DIR}/extensions` second;
  later roots override duplicate IDs. Registry entries retain source root/kind,
  and schemas/assets resolve from that owned root.
- Package mutation methods are
  `extension.package.validate/install/update/remove`. `extension.install` is
  dependency installation for an already registered extension.
- Package install/update and runtime activation/readiness are separate.
- `als-rs extension ...` is offline-first and only best-effort notifies a live
  server after filesystem mutation.
- Targeted reload stops the affected handler, terminates matching FWS transport
  shells by shellspec/current app scope, reloads registry/modules, and waits for
  readiness when requested.
- The installed wheel packages the Rust workspace and builtin extensions.
  Bootstrap distinguishes source checkout from packaged manifests and keeps
  Cargo output under the ALS-RS cache root.
- Detailed map: KB reference sections `Extension registry and lifecycle bridge`
  and `Extension packages and provider notes`.

## Provider quick facts

### Codex

- The `high_context_400k` setting injects a 450k model window and 400k
  auto-compact limit.
- Runtime response schema keys are lowercase. Missing entries may be rebuilt from
  the loaded generated schema bundle.
- ALS-RS schema cache is `${ALS_RS_CACHE_DIR}/codex_app_server_schema` and uses
  experimental schema generation so `excludeTurns` is represented.
- App-server stdout uses `msgspec.json.Decoder`; response waiters resolve in the
  read lane and non-response events enter a Codex-owned async router queue.
- `agent-pty-blocks` is active as stdio with a full enabled-tool list and
  per-turn injection. The retained HTTP shim is not the active path.
- Authentication completion is notification-driven. Do not poll account reads
  while login is pending.

### Copilot

- Vendored SDK drift is isolated behind `protocol_adapter.py` and
  `protocol_registry.py`. Schema and generated/public RPC surfaces can disagree.
- Stable transcript IDs use provider-native message/reasoning IDs, not
  router-local counters that reset on resume.
- Model effort metadata merges top-level and nested capability sources so
  `xhigh` survives.
- Lazy resend is deterministic: cold send miss, resume ack, retry once.
- The FWS wrapper uses framework-shell-owned output subscriptions and writes.

Detailed map: KB reference section `Extension packages and provider notes`.

## Build, search, and contribution rules

- Frontend changes require `npm run typecheck --quiet` and
  `npm run build --quiet`. Source edits are not live until rebuilt.
- Binary-release wheels carry the checked-in Rust static tree as runtime input,
  including `static/dist/codex_agent.js` and the Socket.IO MessagePack parser.
  Release staging excludes only the repository-level output `dist/`; wheel
  construction fails closed when any required binary or frontend payload is
  absent.
- TypeScript is strict and first-party frontend source disallows explicit `any`.
- Run `basedpyright` directly from `PATH`.
- Do not blindly content-search `node_modules/`, `build/`, static `dist/`,
  minified/bundled/maps, temporary worktree builds, conversation caches, or
  framework-shell logs.
- Use structured FWS inspection first for framework-shell logs and targeted
  JSON-aware scripts for conversation JSONL.
- Do not restart the live harness server during ordinary work; it owns the
  current agent connection.
- Do not modify `android/` without directory-specific approval.
- Commit authorship is user-controlled; never add Copilot attribution unless
  explicitly requested for that commit.
- Every commit in this repo requires synchronized Python/Rust version bump and
  push when applicable.
- `ferrous_framework` is a Git submodule. Commit/push its repo first, then commit
  the parent gitlink.
- Detailed map: KB reference section `Repository operations and validation`.
